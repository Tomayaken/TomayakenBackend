# GPSチェックインフロー

## 方針

GPSは位置情報の厳密な証明ではなく、**避難所を見つけるため**に利用する。

- 現在地が避難所に近いだけで、勝手にチェックインされない
- QRコード撮影のために人が一箇所へ集まらない
- 利用者自身による明示的なチェックインになる

当初は避難所に設置したBLE Beacon（iBeacon）で避難所を見つける予定だった。Beaconの調達・設置・設定の手間が大きいため、スマートフォンだけで済むGPSに切り替えた。

## フロー

```text
利用者アプリ (Flutter)
    |
    | 端末のGPSで現在地を取得
    v
GET /api/v1/shelters/nearby?latitude=&longitude=
    |
    | 近い順の避難所（distanceMeters 付き）
    v
「○○小学校が近くにあります」
    |
    | チェックインする世帯メンバーを選び、ボタンを押す
    v
POST /api/v1/shelters/:shelterId/checkins
```

- サーバーは近い順に返すだけで、距離の上限を設けない。どこまでを「近くにある」とみなすかはアプリが決める。
- 避難所どうしが近い場合や、屋内でGPSがずれる場合に備え、いちばん近い避難所だけでなく候補を並べて利用者が選べるようにする。
- 位置情報の権限がない、測位できないなどで避難所が見つからない場合は、避難所一覧（`GET /api/v1/shelters`）から選んで同じチェックインAPIを呼ぶ。サーバーは経路を区別しない。

## 既知の限界

- チェックインAPIは現在地を受け取らず、避難所の近くにいるかを検証しない。そのため現地にいなくてもチェックインできる。現段階ではこれを許容する（運営者が避難者一覧で確認する）。
- 屋内や建物の密集地では、GPSの誤差が数十m以上になることがある。

発展として、避難所で定期的に変化するコードを表示し、チェックイン時にサーバーで検証する方式を検討する（[architecture.md](./architecture.md#10-発展構想)）。
